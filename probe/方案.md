# QAVideo 测试方案

> 版本 v1.0 ｜ 评审对象：QAVideo（AI 视频解析-总结平台）
> 定位：服务端 + Web 端全面测试方案，含自动化框架设计、缺陷定位方法论与 AI 测试实践
> 约束：**只读被测系统，不改动业务代码**；所有测试资产置于 `probe/` 目录

---

## 0. 文档信息

| 项 | 内容 |
| --- | --- |
| 被测系统 | QAVideo：Vue3 + Spring Boot 3.5 + MySQL + Redis + RocketMQ + LangChain4j(DeepSeek) + ffmpeg/VLM |
| 测试范围 | 服务端接口/服务/存储/中间件/异步任务；Web 端交互/播放/状态一致性；AI 能力与降级 |
| 不在范围 | 大模型本身的效果调优、视频转码、容器编排运维 |
| 交付物 | 本方案 + 用例库 + 自动化框架（`probe/`）+ 缺陷看板 + 测试报告 |
| 质量目标 | P0 用例通过率 100%；接口自动化覆盖 15/15 端点；E2E 覆盖 4 条核心链路；无 P0/P1 遗留 |

### 为什么这份方案不是"通用模板"

本方案基于该仓库**已经真实出现过的 6 类缺陷**反向设计（详见附录 A），
每一条测试重点都能追溯到一个已发生的问题或一个已确认的架构风险点。
同时，仓库现状是**只有后端 25 个用例、Web 端 0 测试**，因此方案按"先补高危缺口"排序。

## 1. 被测对象与核心链路

### 1.1 接口清单（15 个端点）

| 模块 | 端点 | 说明 |
| --- | --- | --- |
| 视频 | `POST /api/videos/import-url` | 链接导入（规范化去重） |
| | `GET /api/videos` | 列表分页（page/size/status/keyword） |
| | `GET /api/videos/{id}` | 详情（总结/转写/章节/任务） |
| | `GET /api/videos/{id}/stream` | 播放（**必须支持 HTTP Range**） |
| | `GET /api/videos/{id}/tasks` | 解析历史 |
| | `POST /api/videos/{id}/parse` | 重新解析 |
| | `DELETE /api/videos/{id}` | 删除（含磁盘文件） |
| 上传 | `POST /api/uploads/init` | 创建/恢复会话、秒传短路 |
| | `GET /api/uploads/{uploadId}` | **断点续传查询** |
| | `POST /api/uploads/{uploadId}/chunks/{index}` | 分片上传 |
| | `POST /api/uploads/{uploadId}/complete` | 合并+哈希+去重+入库+派发 |
| | `DELETE /api/uploads/{uploadId}` | 取消并清理 |
| 任务 | `GET /api/tasks/{id}` | 任务进度轮询 |
| | `GET /api/tasks` | 最近任务 |
| 系统 | `GET /api/system/status` `/health` `/ping` | 中间件与 AI 模式诊断 |

### 1.2 四条核心业务链路（E2E 基线）

```
L1 本地导入：拖文件 → init → 分片上传 → complete → 去重入库 → MQ 派发 → 解析 → 详情展示
L2 断点续传：上传中断 → 刷新页面 → 重拖同文件 → 服务端对账 → 续传 → 完成
L3 链接导入：粘贴链接 → URL 规范化 → 去重命中/新建 → 解析 → 列表可见
L4 素材提取：sidecar 字幕 → ASR（语音）→ Vision（画面）→ 降级占位 → DeepSeek 总结
```

## 2. 风险地图与测试重点

风险排序依据：**影响面 × 发生概率 × 定位难度**（定位难度高的优先自动化，因为人工排查成本最高）。

| # | 风险 | 影响 | 触发场景 | 测试重点 |
| --- | --- | --- | --- | --- |
| R1 | 视频无法播放（Range 请求 500） | 致命，功能不可用 | 浏览器播放必然带 Range | 字节级校验 206/Content-Range |
| R2 | LOB 列被 DDL 改小 → 解析结果写不进去 | 致命，静默数据丢失 | 依赖 ORM 自动建表 | 列类型契约 + 大文本写入 |
| R3 | 中间件不可用导致**启动失败** | 高，服务不可用 | Redis/MQ 未就绪 | 降级启动 + 故障注入 |
| R4 | 重复入库（去重失效） | 高，数据脏 | 并发导入 / 参数化链接 | 并发唯一性 + 规范化 |
| R5 | 断点续传丢分片 / 续传错位 | 高，上传失败 | 并行分片、会话过期、状态丢失 | 状态对账 + 幂等重传 |
| R6 | 任务永久 PENDING（MQ 投递丢失/消费者断连） | 高，用户白等 | broker 重启、投递在事务内 | 投递时机 + 幂等 + 可观测 |
| R7 | AI 输出不可信（幻觉/占位文本被当成真实内容） | 中高，误导用户 | 模型不可用时的降级 | 降级可见性 + 失败原因透出 |
| R8 | 配置未生效（环境变量/模型名/编码） | 中，功能静默失效 | 启动方式、平台模型下线 | 配置自检接口 + 启动日志断言 |
| R9 | 大文件 / 超大请求打挂服务 | 中，稳定性 | 2GB 视频、超长标题 | 边界与限流 |
| R10 | XSS/路径遍历/SSRF | 中，安全 | 标题、URL、storagePath | 注入与越权用例 |

## 3. 测试分层策略

| 层级 | 范围 | 工具 | 目标占比 | 现状 |
| --- | --- | --- | --- | --- |
| L1 单元 | 纯逻辑（URL 规范化、摘要引擎、帧命令构造） | JUnit5 + AssertJ | 45% | 已有 14 个 |
| L2 契约/接口 | 15 个端点参数校验、状态码、响应结构 | REST Assured / Playwright APIRequest | 25% | **缺口** |
| L3 集成 | DB/Redis/MQ/文件系统真实交互 | Testcontainers | 15% | 部分（H2 内存） |
| L4 端到端 | 4 条核心链路 | Playwright + 真浏览器 | 10% | **缺口** |
| L5 非功能 | 性能、稳定性、安全、兼容 | k6 / OWASP ZAP / 故障注入 | 5% | **缺口** |

**关键原则**：能用"进程内集成测试"覆盖的，不放到 UI 层；UI 层只验证**只有浏览器才能暴露的问题**（Range 播放、拖拽、刷新后恢复）。

## 4. 服务端测试设计

### 4.1 上传与断点续传（最高优先级）

服务端用 Redis HASH（元数据）+ SET（已收分片）记录状态，磁盘留 `chunk-*.part`，
`init` 时会用磁盘反向对账。这里的状态机必须重点打。

| 用例ID | 场景 | 步骤 | 预期 | 优先级 |
| --- | --- | --- | --- | --- |
| UPL-001 | 正常分片上传 | init(4片) → 依次传 0..3 → complete | 200，文件落盘，sha256 正确，video 入库 | P0 |
| UPL-002 | 断点续传 | init → 传 0,1 → 重新 init(带 uploadId) | `resumed=true`，`uploadedChunks=[0,1]` | P0 |
| UPL-003 | 幂等重传 | 同一 index 重复上传 3 次 | 均 200，进度不重复计数，合并结果字节正确 | P0 |
| UPL-004 | 乱序上传 | 按 3→1→0→2 顺序上传 | complete 成功，文件按 index 顺序拼接 | P0 |
| UPL-005 | 并行分片 | 并发 8 个分片同时上传 | 无丢失（SET 原子），进度=8/8 | P0 |
| UPL-006 | 缺片 complete | 少传 1 片直接 complete | 409，错误信息列出缺失分片号 | P1 |
| UPL-007 | 秒传短路 | 带 contentHash init（已存在） | 不传字节直接返回 `duplicate` | P1 |
| UPL-008 | 大小不符 | 声明 fileSize 与实际不符 | complete 时 400，提示大小不一致 | P1 |
| UPL-009 | 越界分片 | index=-1 / index=totalChunks | 400，越界提示 | P1 |
| UPL-010 | 超限文件 | fileSize > max-file-size | 400，提示上限 | P1 |
| UPL-011 | 会话过期 | 构造过期会话后上传 | 404，提示"会话已过期，请重新初始化" | P1 |
| UPL-012 | 磁盘恢复 | 保留 chunk 文件、清空 Redis 后 init | 磁盘对账，`resumed=true` 且分片数正确 | P1 |
| UPL-013 | 取消清理 | init → 传部分 → DELETE | 会话与临时目录均被清理 | P2 |
| UPL-014 | 孤儿清理 | 造超 TTL 的会话目录，触发定时任务 | 目录被回收，时长不足的会话不受影响 | P2 |
| UPL-015 | 路径穿越 | uploadId 传 `../../etc` | 仅按白名单定位，拒绝非法会话 ID | P0(安全) |

## 6. 自动化测试框架与平台设计（自研）

### 6.1 分层自动化矩阵

```
probe/
├─ backend-it/        # JUnit5 + Testcontainers（MySQL/Redis/RocketMQ 真容器）
├─ api-tests/         # REST Assured 契约与参数化用例
├─ e2e/               # Playwright（真浏览器 + 真文件上传）
├─ perf/              # k6 脚本
├─ chaos/             # 故障注入（停容器/断网/限流）
├─ mock/              # 假 ASR / 假 VLM / 假 ffmpeg（可在无外部依赖下验证 AI 链路）
├─ contracts/         # OpenAPI 契约与前后端一致性校验
└─ tools/             # 自研小工具（见 6.4）
```

### 6.2 关键技术选型

| 目标 | 方案 | 说明 |
| --- | --- | --- |
| 后端集成 | JUnit5 + Testcontainers | 用**真 MySQL** 跑 DDL 契约，避免 H2 掩盖 tinytext 类问题 |
| 接口自动化 | REST Assured + JUnit5 参数化 | 15 个端点全覆盖，断言 code/HTTP/字段类型 |
| 前端组件 | Vitest + @vue/test-utils | 覆盖 useUploader（纯逻辑，性价比最高） |
| 端到端 | Playwright | 支持真实文件拖拽、`page.route` 造异常、网络面板断言 |
| 性能 | k6 | 脚本化、指标可入 CI |
| 契约 | OpenAPI 快照 + 差异告警 | 后端改动导致前端破约时提前拦截 |

### 6.3 前端自动化重点（性价比排序）

1. **useUploader 单元测试**（最高）：断点续传、重试、暂停、秒传分支都是纯逻辑，用假 fetch 即可覆盖 WEB-006~011，执行快、稳定性高。
2. **Playwright E2E**：只覆盖"必须真浏览器"的 WEB-001/008/012/013/018。
3. **视觉回归**：对详情页（含兜底警告条）做截图比对，防止提示被误删。

### 6.4 自研工具（响应"自主开发测试工具/平台"）

| 工具 | 解决的问题 | 实现要点 |
| --- | --- | --- |
| **QAVideo Test Kit** | 测试数据构造繁琐 | 一行代码造"已上传/已解析/失败"三种状态的视频；提供 `upload(file, {interruptAt:2})` 模拟中断 |
| **假 AI 服务桩** | 外部模型不稳定、无法断言 | 本地 HTTP 桩返回固定 ASR/VLM 响应，并**记录收到的请求体**（用于断言"帧是否真的发出去了"） |
| **字节级 Range 校验器** | 视频播放问题难定位 | 下载区间 → 与磁盘文件同偏移逐字节比对，输出首个差异字节位置 |
| **DDL 漂移探测器** | ORM 偷偷改表 | 启动前后快照 `information_schema`（列类型 + CREATE_TIME），差异即报错 |
| **配置自检命令** | "设置了却不生效" | 读取 `/api/system/status`，打印每个能力（AI/ASR/Vision/MQ/Redis）的真实生效状态与原因 |
| **缺陷证据包生成器** | 提单信息不全 | 一键收集：请求/响应、日志片段、DB 快照、截图、环境信息，打包成单文件便于跟踪 |

### 6.5 CI 质量门禁

```
提交 → 单元测试(必过) → 契约校验 → 集成测试(Testcontainers)
     → API 自动化 → E2E 冒烟(4 条主链路) → 覆盖率门禁 → 报告归档
```

门禁建议：
- 单元+集成通过率 100%，API 自动化通过率 ≥ 98%；
- 核心服务类行覆盖 ≥ 70%，新增代码 ≥ 80%；
- E2E 冒烟必须全绿才允许合并；
- 任一 P0 用例失败 → 阻断发布。

## 7. AI 测试实践（两条主线）

### 7.1 主线一：用 AI 提升测试效率

| 实践 | 做法 | 收益 |
| --- | --- | --- |
| 用例生成 | 把 OpenAPI 文档 + 领域说明喂给 LLM，生成边界/异常用例草稿，人工评审后入库 | 用例设计效率提升 |
| 智能造数 | 生成多语言标题、超长 URL、畸形 JSON、畸形 multipart | 覆盖人工想不到的输入 |
| 失败聚类 | 把失败日志/堆栈向量化聚类，识别"同一根因的多条失败" | 减少重复定位 |
| 根因建议 | 把异常栈 + 相关代码片段喂给 LLM，输出候选根因与验证方法 | 缩短 MTTR |
| 视觉断言 | 用 VLM 对截图做语义断言（"出现兜底摘要警告条"），替代脆弱的像素断言 | 降低 UI 用例维护成本 |
| 自愈定位 | 选择器失败时用 LLM 依据 DOM 语义推荐新选择器 | 降低 E2E 脆弱度 |

**边界与纪律**：AI 生成的内容必须人工评审后入库；断言不允许由 LLM 直接判定"通过"，
LLM 只能给建议，最终判定必须落到确定性断言上。

### 7.2 主线二：测试"AI 能力"本身

这是本项目的特色，也是"AI 测试实践"的核心加分项：

| 编号 | 测试点 | 方法 | 判定 |
| --- | --- | --- | --- |
| AIU-001 | **幻觉防护** | 喂入明确标注为占位的素材 | 总结必须如实说"信息不足"，不得编造视频情节 |
| AIU-002 | 降级正确性 | 断开 VLM/ASR/DeepSeek | 必须降级到本地兜底并打标 `mockAi`，不得静默伪装成真实结果 |
| AIU-003 | 可替换性 | 换 base-url/model 指向本地桩 | 无需改代码即可切换，请求格式符合 OpenAI 兼容协议 |
| AIU-004 | 输入构造正确性 | 断言桩收到的请求体 | 图片以 `data:image/jpeg;base64,` 内联；帧数=上传数；Content-Length 有值 |
| AIU-005 | 长输入截断 | 超长转写 | 按 `max-transcript-chars` 截断，不超模型上下文 |
| AIU-006 | 输出健壮性 | 桩返回 ```json 代码块 / 多余散文 / 非法 JSON | 能容错解析；非法时明确失败而非入库脏数据 |
| AIU-007 | 稳定性 | 同一输入重复 5 次 | 结构字段稳定（summary/keywords 不为空），不出现超时空返回 |
| AIU-008 | 成本回归 | 记录每次 tokens | 超阈值告警（防止重试风暴导致费用失控） |
| AIU-009 | 时延监控 | 统计各阶段耗时 | 采集/转写/视觉/总结四段耗时可视化 |
| AIU-010 | 内容安全 | 输入含敏感内容 | 输出符合平台内容规范 |

**AIU-001~004 已被本项目验证有效**：正是靠"假 VLM 桩 + 请求体断言"证明了
"视频帧确实以 base64 图片形式发出"，靠"降级可见性"证明了系统不会用假数据编造总结。

## 8. 缺陷管理：跟踪、定位与推动闭环

### 8.1 分级与响应

| 级别 | 定义 | 响应 | 示例（本项目真实案例） |
| --- | --- | --- | --- |
| P0 | 核心链路不可用 / 数据丢失 / 安全 | 2 小时内定位，当日修复 | 视频无法播放；解析结果因列宽被截断 |
| P1 | 主要功能受损，有绕行方案 | 24 小时内 | 断点续传丢片；MQ 不可用导致启动失败 |
| P2 | 次要功能或体验问题 | 迭代内 | 时长列为空；提示文案歧义 |
| P3 | 建议类 | 排期可选 | 日志级别、文案优化 |

### 8.2 定位方法论（重点：把"偶发"变"必现"）

实际产出的六种手段，建议固化为团队规范：

1. **协议层取证**：不猜 UI，直接 `curl -D -` 看响应头/状态码。
   → 发现"不带 Range 是 200、带 Range 是 500"，一句话锁定播放问题根因。
2. **时间戳取证**：对比系统对象的创建/修改时间。
   → 通过 `information_schema.TABLES.CREATE_TIME` 变化，定位到"是应用启动时 ORM 改了表"。
3. **探针库隔离验证**：用独立空库让 ORM 重建表，观察它生成的真实 DDL。
   → 证明"改注解没用，必须关掉 DDL"。
4. **桩服务对照**：把外部依赖换成可控桩，断言"我们发出去的到底是什么"。
   → 证明视觉请求里确实带了 base64 图片，而非只发了文件名。
5. **字节级比对**：下载区间与源文件同偏移逐字节比较。
   → 证明 Range 返回内容正确，而不只是状态码对。
6. **环境矩阵二分**：同一份代码分别在本机 shell、PS 5.1、容器中运行。
   → 定位到"PS 5.1 + 无 BOM = 语法错误"这类环境特异问题。

### 8.3 缺陷跟踪规范（推动高效解决）

**证据包必须包含**：环境信息、复现步骤（可复制命令）、期望/实际、原始日志、
请求响应原文、DB/文件系统快照、影响面评估、初步根因假设与验证方法。

**推动机制**：
- 每日缺陷例会 15 分钟：只看 P0/P1 与超期项；
- 缺陷超 SLA 自动升级到技术负责人；
- 修复必须附"回归用例 ID"，测试补齐用例后才允许关闭；
- 建立**缺陷→回归用例**映射，每个已修复缺陷都沉淀为自动化用例（附录 A 已给出映射）。

## 附录 A：已发生缺陷复盘 → 回归用例基线

> 这 6 个问题都是本项目真实发生过的，也是本方案所有 P0 用例的来源。

| # | 现象 | 根因 | 定位手段 | 已沉淀的回归用例 |
| --- | --- | --- | --- | --- |
| A1 | 上传的视频无法播放 | `/stream` 的 Range 分支返回 `ResourceRegion` 且预设 `video/mp4`，Spring 转换器只接受 `application/octet-stream` → 500；而浏览器播放必然发 Range | `curl -D -` 对比带/不带 Range 的响应 | STO-002/003、WEB-012/013 |
| A2 | 解析报 `Data too long for column 'highlights'` | Hibernate 6.6 把 LOB 映射为 `tinytext`，且 `ddl-auto=update` 主动 ALTER 把已正确的 `longtext` 改小 | `information_schema` 列类型 + `CREATE_TIME` 时间戳取证 + 探针库复现 | DDL-001~004 |
| A3 | RocketMQ broker 无限重启 | 命名卷以 root 属主挂到镜像内不存在的目录，容器以 uid 3000 运行无法写日志/store，失败后 shutdown 抛 NPE 掩盖真实错误 | 挂载点与容器用户比对 + 启动失败路径分析 | MQ-002/003、CHAOS-002 |
| A4 | 启动直接失败，看不到原因 | 中间件不可用时上下文刷新中断，用户只看到 Maven 的 exit code | 复现 + 堆栈根因提取 | MQ-002、以及"启动错误可读性"检查 |
| A5 | 配置了 Key 却提示未配置 | 环境变量作用域/会话不一致；启动方式未加载 `.env.local` | `/api/system/status` 自检 + 注册表/进程环境对照 | AI-001/006、配置自检工具 |
| A6 | 视觉调用失败：404 → 400 | 平台模型名下线（404 Model not exist）；账户欠费（400 Arrearage） | 错误码逐一区分 + 平台 `/models` 列表 | AI-006/007 |
